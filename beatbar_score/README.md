# beatbar_score —— 实战难度评分器（模型 v0.9）

> English: [README_EN.md](README_EN.md)

给 BeatBar / HMV 打一个可复核、可比较的难度分。
只需要**分段 Beat 表**或**节奏条工程文件**，不需要逐帧识别视频。

---

## 快速开始

### 方式 A：直接运行 exe（不需要装 Python）

发布包里是一个**文件夹**，解压后双击里面的 `BeatBarScore.exe`。

1. 双击打开，界面默认英文，右上角可切 **English / 中文 / 日本語**；
2. 点 **Choose files…** 选一个或多个 `.csv` 分段表 / `.rbarproj` 工程；
3. 如果表格里有 `per8` 列，在 BPM 框里填该曲的 BPM（例如 `129.2`）会更准；
   有总 Beat 数时也可以填在 Total 框里；
4. 点 **Score**，下方会显示评分卡；多个文件时显示汇总表；
5. 结果可以 **Copy result** 复制，或 **Save as text** 存成 txt。

> 示例文件在解压目录的 `examples/` 里：
> `example-Bigmoney.xlsx`（真实作品的分段表，可直接照着填）、
> `template.csv`（空模板）、以及三部参考作品的分段表。

### 方式 B：命令行

```bash
# 单个作品 → 评分卡
python -m beatbar_score data/ref1.csv

# 多个作品 → 汇总表
python -m beatbar_score data/*.csv --table

# 直接读节奏条工作室的工程
python -m beatbar_score "path/to/xxx.rbarproj"

# 英文输出
python -m beatbar_score data/ref2.csv --lang en

# 导出 JSON
python -m beatbar_score data/ref2.csv --json out.json
```

依赖：Python 3.10+、numpy。

### 打包 exe

双击 `build_exe.bat`，产物在 `dist\BeatBarScore.exe`（单文件，约 23 MB，
不需要目标机器装 Python）。

## 输入格式

### 1. 分段表（推荐，适用于别人的成品）

CSV，首行是表头：

```csv
start,end,beats,per8
0,15,0,
15,46,64,
46,76,76,
76,92,32,8.5
```

| 列 | 含义 | 必填 |
|---|---|---|
| `start` / `end` | 区间起止（秒）| ✅ |
| `beats` | 该区间的 Beat 数 | ✅ |
| `per8` | **每 8 个节拍里有几个 Beat**（例如 13）| 可选，填了更准 |

**`per8` 为什么更准**：计时器只能精确到秒，误差会累积；而 `per8` 是从画面上
数"每一组八拍里有几个 Beat"，配合 BPM 换算成频率没有累积误差。
换算公式：`Hz = per8 × BPM / 480`。

文件头可以写元数据（`#` 开头的行）：

```csv
# name: 某作品
# bpm: 129.2
# total: 862
start,end,beats,per8
...
```

- `bpm`：配合 `per8` 使用；命令行 `--bpm` 优先
- `total`：该作品的总 Beat 数，用来消除计时误差（整体缩放使积分等于它）

### 2. 工程文件（适用于自己的谱面）

`.rbarproj` 是 **[RhythmBar-Studio-for-FapHero](https://github.com/Tez192780/RhythmBar-Studio-for-FapHero)**
这个项目的工程文件。本工具只读取其中的谱面音符数据，不修改任何东西。

直接在「选择文件」里打开即可——音符时间精确到毫秒，是四种输入里最准的一种。

## 怎么采数据

**方法 A：读计数器（有计数器时最省事）**

1. 每 7.5 秒暂停一次，记下画面上的 `BEAT n`；
2. 相邻两次相减，就是这 7.5 秒内的 Beat 数；
3. 填成 `start,end,beats` 三列。

> 注意：有的作者计数器到上限会归 1，要留意。

**方法 B：分段表（没计数器时）**

按段落（通常 2–4 小节）数 Beat 数，同时记下这一段的"每 8 拍几个 Beat"。

**方法 C：工程文件**

自己做的谱面，直接给 `.rbarproj`。

## 输出怎么读

| 指标 | 含义 |
|---|---|
| **`S`** | **主分**。100 = 恰好耗尽参考玩家（参考1-SBT 06 到 12:20）的余量 |
| `S_peak` | 最难 60 秒单独造成的伤害 |
| `R60` | 最难一分钟的平均速率（Hz） |
| `T_hi` | 达到 `0.85·R60` 以上的总时长（秒） |
| `N_ch` | 峰值挑战次数（≥4 Hz 且 ≥10 秒） |
| `W` | 递增比：最后两次挑战 / 前两次。>2.5 是渐强型，<1.2 是平铺型 |
| `rest` | 累计有效休息（单段 ≥1.5 秒，开场不计） |
| `φ` | 通关门槛：`S / 100`，即需要参考玩家多少倍的能力 |

**水平划分**：<20 练手 / 20–40 常规 / 40–60 高挑战 / 60–100 顶级 / >100 超出经典量级。

**通关门槛**可以直接对照参考1-SBT 06 的表现：

| 在参考1-SBT 06 撑到 | 能力 φ | 能挑战的 S 上限（留 20% 余量）|
|---|---:|---:|
| 2:30 | 0.14 | 11 |
| 4:05 | 0.23 | 18 |
| 5:20 | 0.35 | 28 |
| 7:00 | 0.48 | 38 |
| 9:15 | 0.69 | 55 |
| 12:20 | 1.00 | 80 |
| 到底 | 1.13 | 90 |

## 模型（v0.9 摘要）

```
r_th = max(0, 1.0 − 2.0·(E − 0.5))       中性阈值随兴奋下移
r ≥ r_th:  dE/dt = +K·[(r−r_th)/(3−r_th)]^1.2
r < r_th:  dE/dt = −2K·0.85^n·(1 − r/r_th)   回落与 E 无关
S = 100·(E_终 − 0.5) / 0.5
```

- `K = 0.000736/s`，由「参考1-SBT 06 在 740 秒恰好耗尽余量」标定
- 超出可持续上限（`4.6 + 3.1·e^(−τ/12)`）的速率会被**削平**，不加分
- 刹车修正：累计休息满 10 秒用掉第一档，之后每 20 秒一档

完整推导见 [`docs/Difficulty Framework v0.9 (ZH).md`](../docs/Difficulty%20Framework%20v0.9%20%28ZH%29.md)；英文版见 [`(EN)`](../docs/Difficulty%20Framework%20v0.9%20%28EN%29.md)。

## 已知局限

| 项 | 说明 |
|---|---|
| 单一锚点 | 只由参考1-SBT 06 一部作品标定 |
| `β`、`α`、`ρ` | 定义性/悲观取值，非拟合 |
| 长条语义 | 未定，当前只按时间点计 |
| 多行/双击 | 按 1 音符 = 1 行程 |
| 内容强度 | 不在模型内（画面越刺激越容易输，这部分没算）|
| 分段粒度 | 7.5 秒以下的节奏变化会被平均掉 |
